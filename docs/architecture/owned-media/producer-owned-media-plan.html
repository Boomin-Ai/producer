01 / Product decision → engineering plan

Built for the room.
Owned down to the frame.

A native media foundation for live guests, audience participation, expressive Sets and editing while the footage is still arriving.

Own the coordination. Reuse proven transport, codecs and operating-system services. Make conversation the protected workload.

What is decided

Producer owns the engine.

Rust owns composition, timing, routing, lifecycle, admission and delivery policy. GPUI owns the operator interface. The target beta does not rely on libOBS or browser rendering for Sets.

LiveKit/WebRTC, platform media frameworks and codec libraries remain building blocks. “Owned” does not mean writing a codec or a congestion controller.

What must be earned

Native is an opportunity, not a result.

Fewer UI/IPC crossings and reusable GPU surfaces can reduce work. Actual frame copies, decode paths, audio playout, SFU region and network conditions determine latency.

No 10× claim, zero-copy claim or end-to-end speedup is established. The pinned SDK is native Rust around libwebrtc C++; a Rust call site alone is not a performance guarantee.

03

One runtime. Separate responsibilities.

Select a block to inspect its owner, real-time boundary and acceptance requirement. Application work cannot sit on the conversational audio path.

Inputs & authority →
Producer-owned engine →
Independent consumers
Immutable media handles + clock-tagged samples cross lanes. UI widgets, JSON and network calls do not.
Deadline lanes

Capture callbacks, audio render, GPU submission and SDK media sinks do bounded work. No disk IO, document validation, network waits, text shaping or unbounded allocation on them.

Control and worker lanes

Compile, prepare, decode, encode, import, thumbnails and durable writes use bounded workers. Stop/revoke commands have reserved admission. Cancellations retain resources until actual destruction completes.

One owner per resource

One device capture feeds authorized consumers; one playback owner drives a speaker. Shared immutable assets are not duplicated players. Extra players are explicit when independent seeking is required.

Consumer isolation

Conversation never waits for an RTMP socket or disk. Stream queues discard/resynchronize by encoded dependency rules; recording reports backpressure and stops safely when it cannot preserve continuity.

04

Conversation first. Production alongside it.

Guests need fast two-way speech. The audience needs a complete production. Those paths share sources but have different buffering and routing needs.

Fast path

Guest ↔ guest / host voice

Direct authorized LiveKit voice tracks, with one playout owner and minimal Producer handoff. A guest does not wait for the host to compose, record and re-encode their own voice back to them.

If Producer must return an authoritative processed voice mix, use an explicit recipient-specific route and do not also play the direct tracks. Compare both designs before extending beyond the initial voice topology.

Production path

Program picture + host/media return

The audience mix includes stage voices once. Guests can see the composed program, but its audible return excludes voices they already receive directly. Share compatible publications rather than encode once per viewer.

A program video of a guest may lag their direct conversational voice. Label this distinction; provide synchronized isolated guest views for conversation and do not claim identical timing on a delayed program monitor.

Visibility is not audibility.

Digital self-return and acoustic echo are different problems. Excluding a guest from their return mix prevents the first. Speaker audio re-entering a microphone requires effective AEC with the actual speaker-reference signal and measured capture/playout delay. A checkbox is not proof.
Stage, private cue and microphone rules
  • Default stage policy: audible while admitted/onstage, even when omitted from the current visual layout. Optional “audio follows visibility” is an authored policy, never an implicit effect of cropping a camera.
  • Host monitoring, audience mute and conversation mute are distinct explicit route controls. Product UI may offer linked controls, but diagnostics show their effective scopes.
  • Host mic capture is shared; processing/publication is not duplicated by adding a Set. Raw originals require explicit recording consent; program mutes are not represented as muting the physical source.
  • Private talkback switches public → muted → named private route at a sample boundary. It excludes public stream, program recording and unrelated guests. Permission failure cannot restore public routing automatically.
  • Private speaker playback can be acoustically recaptured. Gate public mic through the playback tail or require an isolated headset route. Test actual leakage separately from digital routing.
  • Backstage preview/cue needs its own grants and limited subscription budget. Demotion fences public audio immediately without removing the guest’s stable role.

Recovery is a state machine, not “refresh”.

Lifecycle: disconnected → authorizing → subscribing → warming → active → recovering → active, or retired. Stable participant/role identity survives; connection epoch, track publication and source incarnation do not. Deliberate leave cancels retries and releases the appearance lease.

Subscription and quality policy

Subscribe from actual consumers: current layout, next admitted transition, host monitoring, private cue and selected originals. Estimate resolution from output pixels, including planned close-ups; use hysteresis and minimum residency to avoid layer thrash. Off-camera video can be reduced or stopped only when no authorized consumer needs it. Audio membership remains separate.

Use SDK/server congestion controls and supported simulcast/SVC controls. Verify feature support in the pinned Rust SDK before using generic LiveKit documentation as an implementation promise. Network loss may require reduced video quality; never silently change the room’s authored canvas dimensions.

Do not invent a new jitter buffer in front of an existing WebRTC jitter buffer without measuring the added delay. Producer owns a small, explicit presentation handoff and its deadline policy.

05

Time has identity. Buffers have limits.

One continuous production timeline, independent editorial transports, and explicit mappings from device and remote clocks. A wall-clock timestamp is never substituted for a media deadline.

Clock provenance

Frames/samples carry a clock-domain ID, source incarnation, epoch, PTS, duration and timing confidence. Capture time, decoded delivery, intended presentation and actual presentation are different facts.

Audio is continuous

Use sample positions as the audio timeline, with explicit device-clock mapping and bounded drift correction. Choose one physical playout owner. Keep higher precision through processing; apply limiting at the appropriate bus instead of repeatedly clipping every summation.

Video follows presentation deadlines

Select the freshest valid frame for the required time; preserve sender A/V mapping when known. Hold only for a bounded interval, then show a reconnect state. Queue growth must never turn into seconds of hidden latency.

Missing timing stays missing

The pinned stock AudioFrame has PCM/rate/channels, not sender PTS. Existing patched bridges and sender-report maps must be qualified. Arrival-based fallback is labelled estimated and cannot be called lip-sync proof.

A surface includes plane layout/stride, color primaries, transfer, matrix/range and alpha convention. Device loss or an incompatible GPU rejects admission; a measured copy path is an explicit capability. “Zero-copy” is used only for a verified boundary.

06

A crowd should not cost a guest call.

Guest media, audience viewing and audience input are different workloads. Keep their authority and backpressure separate.

Audience clientWatch, vote, react, request stage
Authoritative serviceValidate, deduplicate, version, moderate
Native projectionBounded snapshot + timed accepted events
Component stateVotes, cards, reactions and Show cues

Authoritative actions

Votes, stage admission, moderation and durable chat require server acknowledgement, idempotency and reconnect snapshots. UI can show “sending”; only accepted state updates the official tally or stage policy.

Reuse the existing interaction lifecycle: open, collecting, revealed, closed, cancelled. Two-option votes are the current schema; richer interactions require explicit versions.

Ephemeral expression

Reactions, meters and transient visual cues can be coalesced, rate-limited and dropped when old. Limit simultaneous particles/voices; aggregate bursts instead of spawning one GPU object per event.

Do not put every passive viewer into the host’s media graph. Prefer scalable viewing distribution plus a control channel; only promoted guests acquire admitted media resources.

Audience timing follows the viewing path

A CDN/RTMP viewer may be seconds behind a guest. Interaction windows use server authority plus the relevant program/segment occurrence and a declared delay policy. Exact synchronization is not assumed where player position is unavailable. Late votes get a clear, deterministic outcome.

Boomin owns network authority; Producer owns local execution

Keep existing handles, room links, workspace connections, grants and content services. Beta can require Boomin sign-in as already decided. Keep a provider boundary for future owned-server connections; federation and device-only hosting are later scope, not prerequisites for this engine.

Messages are data, never instructions

Audience text and guest metadata cannot become Assistant tool permissions. Validate role, room/run, size, revision and expiration. Private cue data stays private. Anonymous voter identity is not a guarantee of one unique human.

Transport choices and constraints

LiveKit supports text, data, RPC and state-oriented APIs, but support varies by SDK/version. Do not move every existing Boomin interaction onto a LiveKit data channel just because one exists. Keep authoritative interactions recoverable through existing server APIs and choose transport after measuring reconnect, ordering and rate limits.

Minimum event envelope: logical room/run, interaction or cue occurrence, event ID, accepted server revision, origin role, event kind, permitted payload and timing basis. Maintain receipt IDs for external actions; timeline seek/replay never re-posts messages, re-votes or re-admits a guest.

Agent authoring contract

  1. Read actual room state, active Set/Show, source readiness and supported capabilities.
  2. Build a private transaction with stable IDs and an expected revision.
  3. Validate references, controls, permissions, budgets and output geometry.
  4. Prepare resources, preview the candidate and expose a meaningful diff.
  5. Take explicitly, or within an already granted live-operation scope. Report applied, rejected or superseded truthfully.

Runtime inspection contract

  • Why a guest is audible, visible, subscribed or blocked.
  • Latest source epoch, frame age, timing confidence and readiness.
  • Requested versus effective routing/quality, with reason codes.
  • Current program revision versus private editorial revision.
  • Queue pressure, stale callbacks, underruns and output health.
  • Redacted error context and a user-clicked bug-report action; no automatic public upload of private media or credentials.

Resolve symbolic route policies to explicit admitted source/bus edges before activation. Never evaluate a string policy or execute arbitrary agent-generated code on the real-time path.

Responsive outputs and highly configurable controls

Default room outputs remain 1920×1080 and 1080×1920. Preserve per-room custom dimensions, including square outputs, within device/encoder admission. Sets retain authored geometry and responsive constraints; the Assistant reads current room dimensions when authoring. No stretching a landscape screenshot into a vertical layout.

Control presentation supports compact/equal-width/primary semantics, grouped choices, sliders and conditional visibility across side/top/bottom docks. Native panel headers remain Producer UI colors; Set tokens style the authored control region. Layout/segment operations come first, global Set actions follow unless explicitly rearranged. Content/appearance editing stays in Set Edit; empty sections disappear.

The GPU vocabulary grows through reusable primitives and admitted effects: masks, feathering, text/vector/image surfaces, transforms, gradients, motion and prepared transitions. Add multipass blur/advanced materials only with cache, pass, memory and GPU-time budgets. GPU access is not an instruction to rebuild Three.js wholesale.

08

Deliver proof, then expand the surface.

Seven dependency-led phases. These are engineering gates, not dates or completion percentages. Select a phase for its deliverable, scope and exit evidence.

Critical dependency: P0 → P1 → P2 establishes the guest/media contract before full Set development. Output-adapter research and platform spikes can run alongside it. P3 does not wait for every destination or every visual effect to be complete.
The first bounded implementation job
  1. Freeze the inspected source/SDK manifests and record a real-device LiveKit baseline with the current native guest harness. Preserve failed runs and distinguish prototype counters from full-call evidence.
  2. Define the shared media envelope, audio-bus policy, clock quality states and source/connection epoch rules in the existing Rust contract/media boundary.
  3. Implement an OBS-free guest sink against the existing native renderer and audio owner; retain the reviewed authorization/subscription checks.
  4. Prove one host + one guest with headphones: two-way speech, moving source, paired recording, background editorial seeking and host leave/reopen.
  5. Then qualify speakers/AEC and four guests. If timing metadata is insufficient, resolve the SDK/bridge boundary before layering more buffering or visual complexity onto it.

Deliverable: a repeatable command-driven harness, timestamped/redacted traces, fully decoded recordings and a visible GPUI room. No production desktop replacement at this milestone.

The qualification ladder

A / Deterministic

Fake clocks, real contracts

Clock steps, late frames, generation changes, queue saturation, permission revocation, scene handoff, source deletion and timestamp rounding. Fault injection must preserve expected failures.

B / Synthetic media

Repeatable signals, real transport

Native synthetic guests with flash/click, tones and patterned video; 1 → 4 guests, real LiveKit sessions, program and original recordings. Synthetic proof is labelled, never described as testing a locked phone.

C / Physical devices

What the user actually hears

Mac ↔ Windows, iPhone/Safari and Android/Chrome. Headphones, speakers/double-talk, Bluetooth, lock/background/foreground and network changes. Listen and inspect fully decoded files.

Faults, scale and endurance matrix
  • Network: verified UDP impairment, asymmetric audio/video delay/loss, forced relay, blocked UDP, reconnect and Wi-Fi/cellular change. A hard-loss control must actually halt media; accepting an emulator API call is not proof.
  • Devices: unplug/replug, sample-rate/channel changes, Bluetooth route changes, sleeping/locked host and resumed phone. A format change starts a new source incarnation and appropriate take discontinuity.
  • Outputs: stream disconnect, disk stall/full/removal, encoder saturation, GPU loss, slow preview and simultaneous landscape/vertical recording.
  • Audience: 100 then 1,000 synthetic control clients and 100/1,000 events per second as stress profiles, not advertised capacity. Duplicates, reorder, reconnect snapshots, late votes and reaction floods. Guest latency must remain within the same declared envelope.
  • Duration: 10-minute correctness run → 60-minute four-guest churn run → five-hour speakerphone/production soak; 24-hour recording/take indexing is an additional archival gate.
  • Platforms: Apple Silicon + Intel physical hosts; Windows hardware-encoder families claimed by the release; a declared Linux distro/display/GPU support matrix. Do not mark an untested target supported because Rust compiled.
Diagnostics and repeatable automation

Trace logical participant/source/route IDs, epochs, revision, clock mapping confidence, SDK stats, queue age/bytes/drops, actual presentation times, encoder health and committed take ranges. Use bounded event rings and off-thread aggregation; no per-frame string logging on real-time lanes.

The harness must drive the same operations as GPUI/Assistant. It creates owned test rooms/participants, emits unique audio/video markers, mutes/unmutes, switches layouts, reopens the host, replaces tracks and checks resource return-to-baseline. Reserve stop/cleanup capacity so a stress run can always terminate.

Each report pins source hashes, SDK/native-library versions, features, device/OS/GPU, optimization profile, capture formats, selected SFU region/ICE path and test parameters. Store private recordings locally; exported reports are redacted. Opt-in fleet diagnostics can aggregate join, recovery and deadline metrics without shipping room content.

10

Resolve the surprises before they ship.

Open technical choices are explicit. The plan commits to an owned engine without pretending every adapter or SDK capability is already selected.

Native timing metadata
Stock pinned AudioFrame lacks sender timing; the existing patched decoded-PCM bridge is a specialized dependency. Audit its clock map, resampling, SSRC collisions and multiple-room routing. Missing maps must not silently become trusted capture time.
Audio device + AEC owner
Select one capture/playout/reference chain. Compare SDK-managed native audio against custom CoreAudio/WASAPI/PipeWire plus APM on the same devices. No simultaneous SDK autoplay and Producer monitoring. Speakerphone qualification blocks that claim, even if headset mode passes.
GPU interop
The current guest sink exposes CPU I420 planes; GPU-native decoded frames and texture-backed publication are not established by that interface. Prove each boundary on the pinned SDK. Use one bounded conversion when necessary and measure bytes/copies; do not block beta on an unproven universal zero-copy promise.
SDK evolution
Keep LiveKit/libwebrtc pins and vendored bridge deltas in a dependency manifest. Check current upstream for supported timing/native-surface APIs before patching. Upgrade only with the marker, lifecycle and cross-platform matrix; do not combine an SDK migration with first engine qualification.
Program / conversation mismatch
A composed program is more delayed than direct voice. Explicit monitor modes and return-bus policy prevent duplicated voices; recorded program A/V remains separately synchronized. Do not quietly add program delay to every conversation to hide the difference.
Authority and resurrection
Keep Boomin room/run/lease/admission semantics. Late reconnect, token or track callbacks cannot restore revoked media. App restart and host reopen require fresh authority while preserving logical guest bindings. Media health cannot renew permission.
Cross-platform scope
A single-platform prototype is not an imminent four-platform beta. Windows audio/GPU integration is an early spike, not final polish. Linux’s portal/driver matrix and Intel hardware remain explicit release gates.
Renderer ambition
Retain a 2D retained compositor and reusable material/effect contracts first. Add effect families against actual product fixtures. “10× rendering capability” is an ambition, not a benchmark; visuals must fit the same combined guest/audio/recording budget.
Cutover
Keep production untouched during development. Back up/import user libraries, profiles, identities, assets and room links; do not silently downgrade unsupported Sets. Provide capability reports and actionable import failures. The owned beta has one engine; the old signed production installer remains an explicit rollback, not a hidden second backend.
The first success is not a prettier demo.
It is a conversation that stays fast while everything else happens around it.
