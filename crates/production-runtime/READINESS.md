## Native graphics accounting slice

`core/src/lifecycle.rs::{GraphicsCost, Cost, CAP, estimate}` replaces the old graphics-as-browser model. `core/src/resources.rs` admits each dimension with checked arithmetic, a per-document limit and an exactly doubled two-document workspace limit. The 488-slot retirement allowance is derived from disposable object caps rather than a separate stale literal. Render passes are reserved work; instances are contents of buffers, not 8,192 independent destruction records. Reservation handles remain separately limited to 160 per document.

The deliberately conservative preparation profile charges **every declared source and every authored layout**, including inactive layouts: one output surface/texture/pipeline/pass per layout; one scene state buffer per graphics source; geometry/index/instance buffers and one pipeline per batch; one additional projection texture/pass per scene per layout. The byte model includes assumed single RGBA8 output/projection images and 64-byte instance transforms. It cannot know opaque geometry/material bytes, decode formats, actual attachment counts, MSAA, scratch space or native driver residency. Thus it is **not a complete native allocation estimator or physical memory guarantee**. A future renderer must qualify expanded graph costs and actual resident pools; rendering only active views or sharing immutable assets cannot be assumed here. More complex documents can be rejected by this eager model even if a future qualified native pool could render them.

`core/tests/native_graphics.rs` covers five scenes with no browser slots consumed, independent optional browser capacity, extra-view targets, independent batches sharing assets, every graphics dimension at/over its limit, overflow, failed-admission atomicity and retirement arithmetic. Existing lifecycle/workspace tests now assert nonzero graphics charges through lost swaps, close, exact reconciliation and disposal. The shared ledger test fills two complete caps, rejects borrowing the other document's free capacity and releases only the matching owner. The [source-linked check record](evidence/native-graphics-checks.json) records this slice's local tests and CLI/schema checks; historical benchmark manifests remain unchanged. No new renderer, GPUI build, FPS result or desktop performance improvement is claimed.
