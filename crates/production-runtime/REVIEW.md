# Independent implementation review closure

Reviewed 2026-11-15 by the independent adversarial review agent requested by the user. The reviewer inspected source and regression cases; the parent ran the tests. This follows the earlier plan/specification review and does not replace native or cross-platform qualification.

| Finding | Resolution | Reproduction retained in `core/tests/review_regressions.rs` |
| --- | --- | --- |
| P1: stop could be followed by activation of an old preparation or uncertain swap | Stop advances the runtime generation, supersedes preparations, retires active plans and prevents reconciliation from reactivating the stopped generation. | `stop_fences_old_preparations_and_unknown_reconciliation` |
| P1: replacing only one output could retire resources used by another | First profile explicitly requires full active-output replacement; configuration changes require stop. Rejection precedes swap/retirement. | `partial_output_take_cannot_retire_an_unreplaced_output` |
| P1: renderer updates could grow an unbounded target map | Both sender and receiver require a bounded typed parameter manifest; unknown, duplicate, incomplete-full and incompatible updates reject atomically. | `renderer_rejects_unknown_duplicate_and_wrong_type_targets_atomically` |
| P2: stale release could clear a newer override | Every acquisition has a new token; release checks owner, target and token. | `stale_override_release_cannot_clear_a_newer_acquisition` |
| P2: repeated undo toggled state instead of traversing history | Restore names a specific history entry, validates it at admission, advances revision and consumes history only after a saved result. | `repeated_undo_traverses_history_and_failed_save_does_not_consume_it` |
| P2: reused oversized scratch retained samples from a previous sequence | Evaluation clears the entire caller-provided output slice before writing active samples. | `reusable_scratch_does_not_leak_drivers_from_a_longer_sequence` |
| Follow-up P1: unchanged source aliases could preserve state for different media/resources | Incarnation identity includes resolved immutable file, geometry and material identities. Two additional parent counterexamples have regressions: feasible mixed min/max weighted allocation, and finite-source loop mapping from a negative preroll interval.

The reviewer's final closure found no remaining **concrete blocker in the reviewed implementation** after these fixes. This means the corrected isolated slice is reviewable; it does not certify the unimplemented portions of Phase 1. `READINESS.md` records those gaps explicitly. No review promises an absence of future bugs.

The host separately reserves both writer buffers, and tests check ownership/release rather than equating reservation bytes with RSS. Passing these bounded shapes is not exhaustive native allocation, a long-running recovery soak, a physical platform result or an application performance claim. ## Combined service/graph pressure review

Parent-authored implementation review, not independent sign-off. The new workload combines two near-8-MiB documents, 4,096 spatial nodes, the 512 expanded-track budget, 32,768 keys, procedural effects and sixteen held full-document replies. It exercises saturation without copying rejected input, ordinary shutdown/recovery, held replies across shutdown, historical receipt retry without append, torn-tail repair, full receipt snapshots and corrupt complete-record/checkpoint rejection. Independent maxima are not all jointly admissible: ownership admission rejects excessive component/effect expansion before activation. Existing limits remain unchanged.

Initial RSS failures are preserved rather than dismissed because requested heap passed. The first reply-reuse candidate still failed both shapes. The repeated large allocations were traced to fresh scratch in full-document inspection as well as response materialization/copying. Inspection now recomputes the canonical digest through the document owner's retained bounded scratch, then directly serializes the admitted immutable view into a reusable response buffer. Identity tests retain old reads while editing, undoing, closing and reopening the store; they compare each current digest to the document and saved receipt.

The sixteen-buffer population spans active serialization, unread replies and idle capacity. Buffer return happens before request permit release. Consumer-side return uses `try_lock`; on contention it discards capacity rather than waiting for a worker. The reply slice exposes length, not retained capacity, and over-budget serialization publishes a fixed failure rather than partial JSON. Focused tests cover stale-tail disclosure and bounded writes. Pool capacity is included in measured live heap; no new uncharged cache ceiling is introduced. These guarantees do not promise an absolute RSS cap, hard-real-time deallocation or native callback safety.

The recovery measurement repopulates the new executor's response pool before each steady sample; this is explicitly reported and the gates are unchanged. Earlier and later timings are not a controlled A/B, because warmup workload and host load differ. The source-linked profile, rather than the allocation diagnosis, determines whether the local plateau is qualified. See [pressure workload and preserved failures](PRESSURE-QUALIFICATION.md).

Checkpoint/journal decoding now checks the strict raw envelope without retaining a JSON tree, directly decodes the typed envelope and checks its canonical checksum through the retained store scratch. Replay shares scratch for payload identity, admitted command application, expected outcome digest and bounded receipts. The codec regression checks escaped duplicate keys, dangerous keys, nonfinite numbers, checksum mismatch, trailing data, byte limits and a valid retry after each failure. Existing compatibility and corruption tests still govern legacy checksums, literal metadata and fail-closed store recovery. No checksum, semantic check or receipt outcome is trusted merely because typed deserialization succeeded.


## N1 native-media prototype review

Parent-authored review only; no new independent sign-off. The codec is an optional leaf dependency and never runs on the core evaluator or request/poll path. Worker admission is released on actual exit, exported frames remain charged after close, and a Rust worker panic closes the control handle. Coalescing and stale-publication checks run both before publication and at polling. Actual CFR/VFR/B-frame decode tests compare every displayed/final frame; the discovered DTS-index seek overshoot now triggers bounded earlier-anchor preroll. Forward playback reuses two decoded-frame references and scaling scratch, rather than seeking or spawning a process per frame.

The growing-take prototype limits one writer, pair payload bytes, stream types and contiguous clocks. It publishes an available range only after flushing/syncing both lanes and the manifest. Readers pin that range. The fault test is a pending-manifest collision, not a claim about power-loss/disk-full/removal. The pinned MOV muxer exposed a positive trailer return rejected by the high-level wrapper; the small native trailer call checks negative codes and the subsequent AVIO/fsync state, and both finalized PCM tracks are decoded and checked exactly.

Native C allocations, fully interruptible filesystem/codec calls, file-identity pinning, SAR/rotation/HDR/color correctness, compressed recording/recovery, persistent tail refresh, actual audio devices and GPU/renderer retirement are not yet qualified. `request_latency` includes the async-open queue; worker elapsed time is labeled separately. No low-resolution result is promoted to a 1080p60 or production speed claim. The source-linked failures and earlier core RSS failure remain visible.
